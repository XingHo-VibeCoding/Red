# filter-ui · 筛选交互 Skill

## 何时用

- 给任何"一组条目"加筛选：目录、列表、卡片流、搜索面板。
- 判别信号：需求里出现"筛选 / 过滤 / 搜索 / 只看"这类词，且操作对象是一个**有限集合**。

## 实现清单（调用时逐项检查）

| # | 检查项 | 判定标准 |
|---|---|---|
| 1 | **三态完备** | 有结果（条目随条件变化）/ 无结果（空态必须给"下一步"提示，绝不白屏）/ 清空恢复（一键回到全量） |
| 2 | **反馈可见** | 条件或结果一变，列表立刻响应；空态要有出路（改关键字提示或清空按钮） |
| 3 | **键盘可达** | 输入框可直接聚焦；Esc 关闭面板；结果项可 Tab 到达、Enter 触发 |
| 4 | **无障碍** | 输入框有 aria-label 或可见 label；结果区有 role/aria-label；:focus-visible 有焦点态 |
| 5 | **零后端** | 数据来自本地数组/常量，断网可用；筛选是纯前端状态计算 |

## 验收步骤（实现后逐项执行并记录）

1. 输入一个必然命中的关键字 → 结果条数 > 0 且与预期一致（有结果 ✅/⬜）
2. 输入一个必然不命中的关键字 → 空态可见、有提示、有出路（无结果 ✅/⬜）
3. 点清空 → 输入框清空、全量条目恢复（清空恢复 ✅/⬜）
4. 全程键盘走一遍：聚焦输入 → 输入 → Esc → 重开（键盘可达 ✅/⬜）
5. 连续快速操作 5+ 次不出错、无 JS 报错（健壮性 ✅/⬜）
